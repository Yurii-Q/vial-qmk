# Дашборд: экран, которым управляет ПК

Прошивка SM62 умеет рисовать произвольный экран по данным с компьютера: текст,
полосы прогресса и прямоугольники. Логика (что показать, каким шрифтом, где)
живёт на хосте, прошивка только раскладывает элементы по координатам.

Реализация: `keyboards/ergohaven/sm62/screen_dash.c`, приём пакетов —
`process_raw_hid_data()` в `keyboards/ergohaven/hid.c`, переключение на экран —
`display_modes.c` (`SM62_SCREEN_DASH`, включается при получении первого кадра).

## Модель кадра

Кадр — это набор элементов, у каждого свой `id` (0…23):

| тип | что рисует |
|---|---|
| текст | строка с выбранным шрифтом, выравниванием и цветом |
| полоса | заливка `pos / dur` внутри рамки, цвета задаются |
| прямоугольник | подложка, разделитель, акцентная метка |

Покадровое обновление атомарное: элементы копятся в модели, отрисовка
происходит по `COMMIT`. Промежуточные пакеты экран не перерисовывают.

## Транспорт

- Устройство: `VID 0xE126`, `PID 0xB2` (Space Mission 62), split-клавиатура.
- Интерфейс: usage page `0xFF60` (65376), usage `0x61` (97).
- Output-репорт: **32 байта**, `report id = 0`, хвост добивается нулями.
- Каждый пакет содержит адрес половины: `0` — левая, `1` — правая, `2` — обе.
  Мастер применяет пакет у себя, если адрес совпадает, и ретранслирует на
  вторую половину по split-каналу.

## Протокол

| код | пакет | формат |
|---|---|---|
| `0xC0` | BEGIN | `[0xC0, версия, target, кол-во_элементов]` |
| `0xC1` | TEXT | `[0xC1, target, id, x, y_lo, y_hi, w_lo, w_hi, font\|align<<4, color_lo, color_hi, flags, offset, len, utf8…]` |
| `0xC2` | BAR | `[0xC2, target, id, x, y_lo, y_hi, w_lo, w_hi, h_lo, h_hi, pos(4 LE), dur(4 LE), fg_lo, fg_hi, bg_lo, bg_hi]` |
| `0xC3` | RECT | `[0xC3, target, id, x, y_lo, y_hi, w_lo, w_hi, h_lo, h_hi, color_lo, color_hi, radius]` |
| `0xC4` | COMMIT | `[0xC4, target]` |
| `0xC6` | INVERT | `[0xC6, target, on]` — аппаратная инверсия панели |

Пояснения:

- `x` — 1 байт, `y/w/h` — 2 байта little-endian (0…239 и 0…279).
- `font|align<<4`: младшие 4 бита — код шрифта, старшие — выравнивание
  (`0` влево, `1` центр, `2` вправо).
- `flags` бит 0 — перенос по словам вместо обрезки.
- `offset/len` — позиция и длина куска UTF-8 в строке; строка собирается из
  нескольких пакетов, максимум 96 байт.
- Цвета — RGB565.

## Как отправить текст с ПК

### Одна короткая строка

Строка до 18 байт UTF-8 уходит одним пакетом `0xC1`:

```
[0xC1, 0x00, 0x00,        // TEXT, target=левая, id=0
 0x00, 0x00, 0x00,        // x=0, y=0
 0xDC, 0x00,              // width=220
 0x10,                    // font=0 (Zen 12), align=1 (центр)
 0xFF, 0xFF,              // color=0xFFFF (белый)
 0x00,                    // flags=0
 0x00, 0x05,              // offset=0, len=5
 'H','e','l','l','o', … ]
```

Затем `[0xC4, 0x00]` — commit.

### Длинная строка (до 96 байт)

Строка режется на куски **по границам символов UTF-8** (не по байтам, иначе
LVGL получает битую последовательность и может зависнуть; в прошивке стоит
санитайзер, но полагаться на него не нужно):

```
кусок 0: [0xC1, target, id, x, y(2), w(2), font|align, color(2), flags, 0x00, len, data…]
кусок 1: [0xC1, target, id, x, y(2), w(2), font|align, color(2), flags, 0x12, len, data…]
```

`offset` — смещение в байтах от начала строки. Первый кусок с `offset = 0`
начинает новую строку.

### Полный кадр

```
BEGIN  [0xC0, 0x01, 0x02, 0x04]      // версия 1, target=обе, 4 элемента
TEXT   … id=0, y=0   "Встреча"
BAR    [0xC2, target, 1, 0, 40,0, 220,0, 12,0, pos(4), dur(4), fg(2), bg(2)]
TEXT   … id=2, y=64  "14:00 - 15:00"
RECT   [0xC3, target, 3, 0, 20,0, 220,0, 2,0, 0x2945, 0]
COMMIT [0xC4, 0x02]
```

### Пример на Python (hidapi)

```python
import hid

VID, PID = 0xE126, 0xB2
dev = None
for info in hid.enumerate(VID, PID):
    if info["usage_page"] == 0xFF60 and info["usage"] == 0x61:
        dev = hid.device()
        dev.open_path(info["path"])
        break

def send(payload: bytes) -> None:
    buf = bytes(payload[:32]).ljust(32, b"\x00")
    dev.write(b"\x00" + buf)          # report id 0 + 32 байта

def text(target, element_id, x, y, width, font, align, color, value):
    data = value.encode("utf-8")[:96]
    offset = 0
    while offset < len(data):
        cut = min(offset + 18, len(data))
        while cut > offset and cut < len(data) and (data[cut] & 0xC0) == 0x80:
            cut -= 1
        chunk = data[offset:cut]
        send(bytes([0xC1, target, element_id, x,
                    y & 0xFF, y >> 8, width & 0xFF, width >> 8,
                    (font & 0x0F) | ((align & 0x0F) << 4),
                    color & 0xFF, color >> 8,
                    0, offset, len(chunk)]) + chunk)
        offset = cut

send(bytes([0xC0, 0x01, 0x02, 0x01]))      # BEGIN: обе половины, 1 элемент
text(2, 0, 0, 10, 220, 0, 1, 0xFFFF, "Привет")
send(bytes([0xC4, 0x02]))                  # COMMIT
```

Полноценная реализация на Swift (макеты, цвета, анимация полос) — в проекте
`sm62` (файл `sm62.swift`, функции `dashBegin/dashText/dashBar/dashCommit`).

## Шрифты

| код | шрифт |
|---|---|
| 0 | Zen Medium 12 |
| 1 | Zen Medium 14 |
| 2 | Zen Medium 16 |
| 3 | Zen Medium 20 |
| 4 | Zen Regular 24 |
| 5 | Zen Medium 28 |

Диапазон глифов: ASCII 32–127 и кириллица 1040–1103. Символы вроде `·`, `–`,
`→`, эмодзи не рисуются — используйте ASCII (`-`, `,`, `|`).

Шрифты 12 и 14 генерируются скриптом `scripts/gen-fonts-dash.sh`
(см. `gen-fonts.sh` в проекте sm62), остальные уже есть в прошивке.

## Безопасная область

Экран 240×280, скругления срезают углы. Прошивка сама сдвигает элементы:

```c
#define SM62_DASH_PAD_LEFT 12
#define SM62_DASH_PAD_TOP 8
```

Рабочая область получается 220×264: координаты с хоста считаются от `0,0`
внутри неё.

## Ограничения и подводные камни

- До 24 элементов на кадр, текст до 96 байт.
- Тип элемента нельзя менять «на лету» без пересоздания объекта — прошивка это
  делает сама, но лучше держать `id` за постоянным смыслом.
- Прямоугольник всегда уходит на задний план (`lv_obj_move_background`), поэтому
  его удобно использовать как подложку под текст. Без этого LVGL рисовал бы
  позже созданный прямоугольник поверх надписи.
- Инверсия (`0xC6`) применяется в `housekeep`, поэтому срабатывает не мгновенно,
  а с задержкой до одного тика главного цикла. Это сделано специально: вызов
  драйвера из обработчика USB приводил к дедлоку с идущим SPI-флашем.
- Полный кадр на вторую половину идёт через split-RPC (буфер 40 байт), поэтому
  доезжает за доли секунды; частые полные кадры лучше не гонять.
- Частые обновления полосы заставляют экран перерисовываться — на хосте имеет
  смысл обновлять полосу не чаще, чем меняется её заметная часть.

## Сборка

```sh
# линкеру нужен реальный размер флеша, иначе регион 2 МиБ и прошивка не влезает
make ergohaven/sm62:v1 EXTRALDFLAGS="-Wl,--defsym=FLASH_LEN=4194304"
```

Прошивка одинаковая для обеих половин (сторона определяется пином `SPLIT_HAND_PIN`).
